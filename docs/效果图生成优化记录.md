# 效果图生成优化记录

更新日期：2026-07-16

本文档用于记录“效果图生成模块”的当前实现标准、接口链路、数据关系、关键取舍和历史废弃方案。

重点原则：

```text
1. 效果图生成模块和 AI 装修顾问模块必须分开，不把代码和产品语义糅合到一起。
2. 顶部“平面户型 · 立体图”是户型结构预览，不是装修效果图。
3. 下方“全屋效果图方案”才展示装修后的真实效果图。
4. 用户上传户型图后，必须先完成户型解析，再生成效果图。
5. 生成效果图不使用 mock。
6. 先生成全屋覆盖封面图，各空间效果图由用户手动按需生成。
7. 2D 和 3D 都支持，但二者展示和生成逻辑必须分开。
```

## 1. 当前最终方案

当前效果图生成模块采用以下产品链路：

```text
用户上传户型图
-> 后端保存户型原图
-> 创建 design_project
-> 创建 design_floor_plan
-> 前端自动进入户型解析中
-> 解析完成后回填户型、面积、空间、动线、门窗、采光、结构风险
-> 自动生成“平面户型 · 立体图”
-> 用户选择装修偏好
-> 用户点击“生成全屋覆盖图”
-> 生成一张 2D 全屋覆盖封面图
-> 用户切换到 3D 时，可手动生成“全屋3D立体图”
-> 用户点击右侧某个空间时，只生成这个空间的 2D 或 3D 效果图
-> 用户可放大预览并旋转图片
```

为什么这样做：

```text
1. 全屋主图优先让用户快速看到整体方案。
2. 单空间图按需生成，避免一次点击触发大量生图请求。
3. 2D 负责真实室内装修氛围，3D 负责空间关系和立体感。
4. 顶部户型立体图只表达结构识别结果，避免和装修效果图混淆。
```

## 2. 模块边界

### 2.1 AI 装修顾问

定位：

```text
负责知识库问答、装修知识咨询、依据引用、文字建议。
```

不负责：

```text
不负责上传户型图。
不负责生成装修效果图。
不负责保存 design_projects、design_floor_plans、design_renders。
```

### 2.2 效果图生成模块

定位：

```text
负责户型图上传、户型解析、户型结构预览、全屋效果图、空间效果图。
```

不负责：

```text
不负责知识库问答。
不把“参考来源”“知识库依据”展示逻辑混入效果图页面。
```

## 3. 页面区域说明

### 3.1 户型图上传区

文件：

```text
apps/web/src/app/components/design-workspace.tsx
apps/web/src/app/api/design/floor-plan/route.ts
```

职责：

```text
1. 用户必须上传户型图后才能生成效果图。
2. 支持 JPG、PNG、WEBP、PDF。
3. 单文件最大 15MB。
4. 上传成功后自动进入“解析中”。
5. 上传、解析、生成户型立体图过程中，上传按钮禁用并显示 loading。
```

关键状态：

```text
uploading：正在上传户型图。
analyzing：正在解析户型。
structureRendering：正在生成户型立体结构图。
floorPlanBusy：上述任一状态为 true 时，禁止重复上传。
```

为什么这样做：

```text
上传户型图会创建新的 project 和 floor_plan。
如果用户在解析过程中重复上传，容易产生多条项目记录和状态错乱。
因此把“上传 -> 解析 -> 结构图生成”视为一个连续流程。
```

### 3.2 平面户型 · 立体图

文件：

```text
apps/web/src/app/components/design-workspace.tsx
apps/web/src/app/api/design/floor-plan/[id]/structure-render/route.ts
```

职责：

```text
1. 在户型解析完成后自动生成。
2. 生成的是户型结构可视化图，不是装修效果图。
3. 图片地址写入 design_floor_plans.analysis_result.structure_render。
4. 不写入 design_renders。
5. 支持单独放大预览。
```

生成目标：

```text
3D floor plan visualization
整套房完整入镜
墙体有厚度
房间分区清楚
门洞、窗洞、阳台、厨房、卫生间位置清楚
少量极简家具作为比例参照
```

明确禁止：

```text
真实装修效果图
单个客厅照片
施工蓝图
手绘草图
```

为什么这样做：

```text
用户上传的是平面户型图。
解析完成后需要一个视觉反馈，告诉用户系统识别到了空间结构。
但这张图不能和真正的装修效果图混在一起，否则用户会误以为已经生成装修方案。
```

### 3.3 引导式生成意图

文件：

```text
apps/web/src/app/components/design-workspace.tsx
```

当前问题：

```text
用户自由输入差异很大。
如果只给一个大文本框，后端 prompt 很难稳定。
```

当前方案：

```text
通过引导问题收集偏好：
1. 你更希望家里是什么感觉？
2. 主要居住成员是？
3. 这次更在意什么？
4. 预算倾向是？
5. 还有什么特别要求？
```

关键方法：

```text
buildIntentFromGuide()
把用户选择和补充描述合并成 intentText。

buildDesignPreferences()
把引导结果整理成结构化偏好，后端写入 design_projects.extracted_preferences。
```

为什么这样做：

```text
结构化偏好比纯自由文本更稳定。
后续排查某张图为什么这样生成，也能从 extracted_preferences 追溯。
```

### 3.4 全屋效果图方案区

文件：

```text
apps/web/src/app/components/design-workspace.tsx
apps/web/src/app/api/design/jobs/route.ts
apps/web/src/app/api/design/jobs/[id]/route.ts
apps/web/src/app/api/design/jobs/[id]/spaces/route.ts
```

职责：

```text
1. 展示装修后的真实效果图。
2. 支持 2D效果 / 3D立体 切换。
3. 2D 和 3D 使用同一张 design_renders 表，通过 metadata.render_mode 区分。
4. 缩略图只展示当前模式下的图片。
5. 放大预览支持旋转。
```

2D 定义：

```text
真实室内装修效果图。
重点看材质、灯光、软装、氛围和落地效果。
```

3D 定义：

```text
装修后的三维立体轴测图。
重点看空间体量、空间关系、家具布局和全屋结构感。
```

注意：

```text
这里的 3D 不是顶部“平面户型 · 立体图”。
顶部图偏结构识别。
下方 3D 偏装修方案展示。
```

## 4. 当前生成规则

### 4.1 全屋覆盖封面图

触发：

```text
用户点击“生成全屋覆盖图”。
```

接口：

```text
POST /api/design/jobs
```

当前只生成：

```text
全屋 · 全屋覆盖封面图
metadata.render_role = whole_home_cover
metadata.render_mode = 2d
```

生成要求：

```text
1. 必须是真实装修后的全屋覆盖封面图。
2. 不用单个客厅图冒充全屋。
3. 允许一张图内用多个真实室内分镜覆盖主要空间。
4. 所有分镜保持同一套风格、材质、色系、灯光和家具语言。
5. 不出现文字标题、房间标签、尺寸标注和图纸符号。
```

明确禁止：

```text
户型立体图
俯视轴测图
剖切模型图
dollhouse
平面户型图
2D 图纸
施工图
手绘图
单客厅图冒充全屋
```

为什么这样做：

```text
用户要求第一张图必须能代表全屋。
但如果让模型直接生成一个“全屋俯视图”，容易退化成户型图或模型图。
所以当前采用“全屋覆盖封面图”的方式：
既要覆盖主要空间，也要保持真实装修效果。
```

### 4.2 空间效果图按需生成

触发：

```text
用户在右侧“空间效果图”列表点击某个空间。
```

接口：

```text
POST /api/design/jobs/[id]/spaces
```

当前规则：

```text
1. 一次请求只生成一个空间。
2. 不循环 floorPlan.spaces。
3. 不自动补齐所有空间。
4. 2D 模式点击空间，只生成该空间 2D 图。
5. 3D 模式点击空间，只生成该空间 3D 图。
6. 同一个 job + spaceName + renderMode 已存在时，直接返回已有图。
```

为什么这样做：

```text
之前自动生成所有空间会导致：
1. 一次点击触发大量生图请求。
2. 等待时间过长。
3. 生图费用不可控。
4. 用户可能只想看其中几个空间。

现在改成按需生成后，速度、费用和用户控制感都更好。
```

### 4.3 空间图必须参考全屋覆盖封面图

后端约束：

```text
1. job.status 必须是 completed。
2. 必须存在 space_name = '全屋' 的全屋覆盖封面图。
3. 优先读取 wholeHomeRender.storage_path，把本地图片转成 data URL。
4. 如果历史记录没有 storage_path，但 image_url 是公网地址，则用公网 URL。
5. 如果拿不到参考图，拒绝生成空间图。
```

metadata 追溯字段：

```text
parent_render_id
parent_render_url
generation_relation = strict_reference_from_whole_home_cover
reference_input_mode = data_url 或 public_url
render_mode = 2d 或 3d
```

为什么这样做：

```text
空间图不能变成一套新的独立装修方案。
它必须和全屋覆盖封面图保持同一套风格、色系、材质和家具语言。
当前通过“参考图输入 + prompt 约束 + metadata 追溯”实现同源关系。
```

边界：

```text
这不是像素级裁剪。
当前是参考图驱动的同源生成。
如果未来要真正从全屋图里裁切/局部重绘，需要图像分割、区域定位和局部重绘能力。
```

### 4.4 全屋 3D 立体图

触发：

```text
用户切换到 3D立体。
当前模式无图时，点击“生成全屋3D立体图”。
```

接口：

```text
POST /api/design/jobs/[id]/spaces
body.renderMode = "3d"
body.spaceName = "全屋"
```

生成要求：

```text
1. 装修后的 3D furnished apartment cutaway render。
2. 45 度斜俯视轴测视角。
3. 开顶户型。
4. 低矮墙体。
5. 所有主要空间尽量同时入镜。
6. 展示真实家具、柜体、灯光、软装、地面、墙面和窗户。
7. 干净白色背景。
```

明确禁止：

```text
普通单房间摄影图
纯结构白盒模型
平面户型图
蓝图
施工图
文字标签
尺寸标注
多宫格拼图
```

为什么这样做：

```text
用户要的 3D 是类似装修平台里的全屋立体结构效果。
它不是顶部的户型结构图，也不是普通室内照片。
```

## 5. 数据表关系

### 5.1 design_projects

职责：

```text
一条效果图方案项目。
上传户型图时创建。
后续 floor_plan、generation_job、renders 都归属这个 project。
```

关键字段：

```text
title：项目标题。
status：uploaded / generating / completed / failed。
intent_text：用户最终生成意图。
extracted_preferences：结构化偏好。
```

### 5.2 design_floor_plans

职责：

```text
保存用户上传的户型图和 AI 解析结果。
```

关键字段：

```text
project_id：所属项目。
file_url：户型图访问地址。
storage_path：本地存储路径。
analysis_status：pending / running / completed / failed。
house_type：户型。
area：面积。
spaces：空间列表。
circulation：动线描述。
analysis_result：门窗、采光、结构风险、户型立体图等扩展结果。
```

structure_render 存储位置：

```text
design_floor_plans.analysis_result.structure_render
```

原因：

```text
户型立体结构图属于户型解析结果的可视化，不属于装修效果图。
所以不写入 design_renders。
```

### 5.3 design_generation_jobs

职责：

```text
记录一次全屋覆盖封面图生成任务。
空间图也挂在这个 job 下，便于追溯同一套方案。
```

关键字段：

```text
project_id
floor_plan_id
status
progress
prompt
provider
model
request_payload
response_payload
error_message
```

### 5.4 design_renders

职责：

```text
保存装修效果图。
包括 2D 全屋覆盖封面图、2D 空间效果图、3D 全屋立体图、3D 空间立体图。
```

关键字段：

```text
project_id
job_id
space_name
view_name
image_url
thumbnail_url
storage_path
sort_order
metadata
```

metadata 关键字段：

```text
render_mode：2d 或 3d。
render_role：whole_home_cover 或 space_derived。
source：dashscope_image_generation。
task_id：DashScope 任务 id。
storage_path：本地图片路径。
parent_render_id：空间图关联的全屋覆盖封面图 id。
parent_render_url：空间图关联的全屋覆盖封面图 URL。
generation_relation：生成关系说明。
reference_input_mode：参考图输入方式。
design_preferences：本次生成使用的结构化偏好。
```

## 6. 接口链路

### 6.1 上传户型图

```text
POST /api/design/floor-plan
```

文件：

```text
apps/web/src/app/api/design/floor-plan/route.ts
```

职责：

```text
1. 校验文件类型和大小。
2. 创建 design_projects。
3. 保存户型图文件到本地 public/uploads。
4. 创建 design_floor_plans。
5. 返回 project 和 floorPlan。
```

### 6.2 解析户型图

```text
POST /api/design/floor-plan/[id]/analyze
```

职责：

```text
1. 真实解析户型图。
2. 回填户型、面积、空间、动线、门窗、厨卫、阳台、采光等。
3. 更新 design_floor_plans.analysis_status。
```

### 6.3 生成户型立体结构图

```text
POST /api/design/floor-plan/[id]/structure-render
```

文件：

```text
apps/web/src/app/api/design/floor-plan/[id]/structure-render/route.ts
```

职责：

```text
1. 读取 design_floor_plans 解析结果。
2. 构造户型结构图 prompt。
3. 调用 DashScope 生成 3D floor plan visualization。
4. 图片保存到本地。
5. 结果写入 analysis_result.structure_render。
```

### 6.4 生成全屋覆盖封面图

```text
POST /api/design/jobs
```

文件：

```text
apps/web/src/app/api/design/jobs/route.ts
```

职责：

```text
1. 校验 projectId 和 floorPlanId。
2. 要求户型解析完成。
3. 创建 design_generation_jobs。
4. 调用 DashScope 只生成一张“全屋 · 全屋覆盖封面图”。
5. 写入 design_renders。
6. 更新 job 和 project 状态。
7. 返回 job 和 renders。
```

注意：

```text
这个接口不自动生成各空间图。
```

### 6.5 查询生成任务

```text
GET /api/design/jobs/[id]
```

文件：

```text
apps/web/src/app/api/design/jobs/[id]/route.ts
```

职责：

```text
1. 返回 generation_job。
2. 返回当前 job 下所有 renders。
3. renders 必须包含 metadata，前端依赖 render_mode 分开显示 2D 和 3D。
```

### 6.6 按需生成空间图

```text
POST /api/design/jobs/[id]/spaces
```

文件：

```text
apps/web/src/app/api/design/jobs/[id]/spaces/route.ts
```

职责：

```text
1. 一次只处理一个 spaceName。
2. 根据 renderMode 生成 2D 或 3D。
3. 查重 job + spaceName + renderMode。
4. 强制读取全屋覆盖封面图作为参考图。
5. 调用 DashScope 生成图片。
6. 保存图片。
7. 写入 design_renders。
```

## 7. DashScope 生图封装

文件：

```text
apps/web/src/lib/ai/dashscope-images.ts
```

环境变量：

```text
DASHSCOPE_API_KEY：必填，真实生图服务 Key。
DASHSCOPE_IMAGE_MODEL：普通文生图模型，默认 wan2.7-image。
DASHSCOPE_REFERENCE_IMAGE_MODEL：带参考图模型，默认 wan2.7-image-pro。
DASHSCOPE_IMAGE_SIZE：默认 1K。
DASHSCOPE_IMAGE_TIMEOUT_MS：默认 180000。
DASHSCOPE_IMAGE_THINKING_MODE：默认 false。
```

模型选择：

```text
没有参考图：
使用 DASHSCOPE_IMAGE_MODEL。

有参考图：
使用 DASHSCOPE_REFERENCE_IMAGE_MODEL。
```

为什么这样做：

```text
全屋覆盖封面图和户型结构图是普通文生图。
空间图需要参考全屋覆盖封面图保持风格一致，所以使用支持 image + text 输入的模型。
```

图片落地：

```text
DashScope 返回的是临时图片 URL。
后端必须下载图片并保存到项目本地 uploads 目录。
前端只展示本项目自己的图片 URL，避免临时链接过期。
```

## 8. 前端核心方法

文件：

```text
apps/web/src/app/components/design-workspace.tsx
```

关键方法：

```text
uploadFloorPlan()
上传户型图，成功后启动 analyzeFloorPlan()。

analyzeFloorPlan()
调用户型解析接口，成功后启动 createStructureRender()。

createStructureRender()
生成顶部“平面户型 · 立体图”。

createGenerationJob()
只生成 2D 全屋覆盖封面图。

createSpaceRenderForJob()
按 jobId + space + renderMode 生成一个空间图。

createSpaceRender()
右侧空间按钮入口，只生成当前被点击空间。

create3dRenders()
只生成“全屋 · 全屋3D立体图”。

switchRenderMode()
切换 2D / 3D，并自动选中当前模式第一张图。

openRenderPreview()
打开效果图放大预览。

rotatePreview()
旋转放大预览图片。
```

关键状态：

```text
floorPlan：当前户型图和解析结果。
generationJob：当前全屋覆盖封面图任务。
renders：当前任务下的所有装修效果图。
activeRenderMode：当前展示 2D 还是 3D。
activeRenderId：当前选中的效果图。
generatingSpaceKey：当前正在生成的空间，格式为 mode:spaceName。
previewRender：当前放大的装修效果图。
previewRotation：放大预览旋转角度。
structurePreviewOpen：顶部户型结构图放大状态。
failedImageIds：加载失败图片集合。
```

## 9. 已废弃方案

### 9.1 废弃：单个客餐厅图冒充全屋

废弃原因：

```text
用户要求第一张图能代表全屋。
单个客厅或餐厅图虽然真实，但不能覆盖卧室、厨房、卫生间、阳台等空间。
```

当前替代：

```text
全屋覆盖封面图。
```

### 9.2 废弃：2D 全屋图生成户型总览图

废弃原因：

```text
户型总览图容易变成结构图、模型图、俯视轴测图或带文字标签的平面图。
这不符合用户要求的真实装修效果。
```

当前替代：

```text
2D 模式生成真实装修效果图。
结构图只放在顶部“平面户型 · 立体图”。
```

### 9.3 废弃：自动生成所有空间图

废弃原因：

```text
一次点击触发太多请求。
等待慢。
费用不可控。
用户不一定需要全部空间。
```

当前替代：

```text
空间图手动按需生成。
点击哪个空间，只生成哪个空间。
```

## 10. 当前能力边界

当前可以做到：

```text
1. 上传 JPG / PNG / WEBP / PDF 户型图。
2. 真实解析户型、面积、空间、动线、门窗、采光等信息。
3. 生成户型立体结构图。
4. 生成 2D 全屋覆盖封面图。
5. 参考全屋覆盖封面图，按需生成单空间 2D 图。
6. 生成全屋 3D 立体图。
7. 按需生成单空间 3D 图。
8. 2D / 3D 分模式展示。
9. 图片放大预览和旋转。
10. 图片落本地存储并写入数据库。
```

当前不能承诺：

```text
1. 不是完整 BIM 模型。
2. 不能自动识别真实承重墙并给出可施工拆改方案。
3. 不能保证像素级从全屋封面图裁切出某个空间。
4. 不能替代专业设计师、结构工程师和物业审批。
5. 不能保证 AI 生成图和真实施工 100% 一致。
```
