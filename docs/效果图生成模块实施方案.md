# 效果图生成模块实施方案

## 模块定位

效果图生成是独立于 AI 装修顾问的业务模块。

- AI 装修顾问：负责知识库问答、施工风险、材料建议、预算合同等咨询。
- 效果图生成：负责上传户型图、解析户型、生成全屋效果图、展示生成结果。

两个模块在页面和代码上保持边界清晰。效果图模块可以调用知识库做方案检查，但不把知识库聊天界面混入生成页面。

## 当前产品原则

1. 户型图必传。
2. 按户型图自动解析空间，不让用户手动勾选客厅、卧室、厨房等空间。
3. 生成目标是全屋效果图，不是单个局部空间图。
4. 用户用自然语言描述偏好，系统自动提取风格、预算、色系、家庭情况等参数。
5. 初始化页面不展示假户型、假方案、假效果图、假队列。
6. 未上传户型图前，生成按钮禁用。
7. 生成结果支持多视角缩略图、放大查看、保存、导出、知识库检查。

## 初始页面状态

用户首次进入效果图生成页时：

- 户型图状态：待上传。
- 户型解析：户型待识别、面积待识别、空间待识别、动线待识别。
- AI 生成意图：输入框为空，只展示 placeholder。
- 示例需求：
  - 现代简约 · 明亮通透 · 有小孩
  - 奶油风 · 温柔耐看 · 收纳多
  - 原木风 · 自然放松 · 预算中等
- 全屋效果图方案：展示空状态，不展示假效果图。
- 生成队列：等待上传户型图后创建。
- 生成按钮：禁用。

## 用户主流程

1. 用户进入效果图生成模块。
2. 用户上传户型图。
3. 系统上传文件到 Supabase Storage。
4. 系统创建或更新设计项目。
5. 系统解析户型图，得到户型、面积、空间、动线等信息。
6. 用户输入自然语言生成意图，或点击示例需求。
7. 用户点击生成全屋效果图。
8. 后端创建生成任务。
9. 前端轮询任务状态。
10. 生成完成后展示全屋效果图、多空间视角图和方案说明。
11. 用户可以保存、导出、放大查看，或用知识库检查方案风险。

## 页面流程与数据表对应关系

效果图生成模块的数据结构必须按页面操作流程理解，避免后端表设计和用户使用路径脱节。

### 页面顺序 1：上传户型图

对应表：

- `design_floor_plans`

记录内容：

- 上传的户型图文件。
- 文件名。
- 文件地址。
- 上传状态。
- 解析状态。
- 解析结果。

### 页面顺序 2：AI 生成意图

对应表：

- `design_projects`

记录内容：

- 用户这次全屋效果图生成项目。
- 用户输入的自然语言需求。
- 系统抽取出的风格、预算、色系、居住需求。
- 项目整体状态。

### 页面顺序 3：户型解析

对应表：

- `design_floor_plans`

记录内容：

- 户型。
- 面积。
- 空间列表。
- 动线。
- 解析原始 JSON。

### 页面顺序 4：生成全屋效果图

对应表：

- `design_generation_jobs`

记录内容：

- 生成任务。
- 任务状态。
- 进度。
- prompt。
- 错误原因。

### 页面顺序 5：展示效果图结果

对应表：

- `design_renders`

记录内容：

- 全屋效果图。
- 各空间视角图。
- 缩略图。
- 排序。
- 图片地址。

### 页面顺序 6：知识库检查方案

对应表：

- `design_reviews`

记录内容：

- 施工风险。
- 材料建议。
- 预算风险。
- 知识库检查结果。

### 页面流程顺序

```text
上传户型图 -> AI 生成意图 -> 户型解析 -> 生成任务 -> 效果图结果 -> 知识库检查
```

### 数据库建表顺序

页面上虽然先上传户型图，但数据库里户型图需要挂到项目上，所以必须先建项目表。

```text
design_projects -> design_floor_plans -> design_generation_jobs -> design_renders -> design_reviews
```

## 前端状态设计

效果图生成页建议至少支持以下状态：

- `idle`：未上传户型图。
- `uploaded`：户型图已上传，等待解析。
- `analyzing`：正在解析户型图。
- `ready`：解析完成，可生成。
- `generating`：正在生成效果图。
- `completed`：生成完成。
- `failed`：上传、解析或生成失败。

## API 建议

### 上传户型图

`POST /api/design/floor-plan`

职责：

- 接收户型图文件。
- 上传到 Supabase Storage。
- 创建 `design_projects` 和 `design_floor_plans`，或更新当前项目。
- 返回项目 ID、文件 URL、初始解析状态。

### 创建生成任务

`POST /api/design/jobs`

职责：

- 校验项目是否已有户型图。
- 读取用户生成意图和户型解析结果。
- 创建 `design_generation_jobs`。
- 返回 job ID。

### 查询生成任务

`GET /api/design/jobs/[id]`

职责：

- 返回任务状态、进度、错误原因。
- 如果任务完成，返回生成结果列表。

### 查询项目结果

`GET /api/design/projects/[id]/renders`

职责：

- 返回项目下所有效果图、缩略图、空间视角信息。

### 知识库检查方案

`POST /api/design/projects/[id]/review`

职责：

- 把户型解析、生成意图、方案说明、材料建议传给知识库检查逻辑。
- 输出施工、材料、预算和落地风险。

## 实施顺序

### Step 1：确认数据结构

目标：

- 按页面流程确认 5 张核心表。
- 明确每张表负责保存哪个页面环节的数据。

产物：

- `design_projects`
- `design_floor_plans`
- `design_generation_jobs`
- `design_renders`
- `design_reviews`

确认后进入 Step 2。

### Step 2：补 Supabase 建表 SQL

目标：

- 生成可直接在 Supabase SQL Editor 执行的 SQL。
- 包含主键、外键、状态字段、JSON 字段、时间字段和索引。

注意：

- 先建 `design_projects`。
- 再建依赖项目 ID 的其他表。
- SQL 需要支持重复执行时不报错。

确认后进入 Step 3。

### Step 3：创建 Supabase Storage bucket

目标：

- 创建户型图和效果图使用的存储 bucket。
- 至少需要支持户型图上传和生成图访问。

建议 bucket：

- `design-assets`

目录建议：

- `floor-plans/`
- `renders/`
- `thumbnails/`

确认后进入 Step 4。

### Step 4：做上传户型图 API

目标：

- 前端上传户型图。
- 后端保存文件到 Supabase Storage。
- 后端写入 `design_projects` 和 `design_floor_plans`。
- 页面从待上传进入上传成功或解析中状态。

建议接口：

- `POST /api/design/floor-plan`

确认后进入 Step 5。

### Step 5：前端接真实上传状态

目标：

- 上传按钮接真实文件选择。
- 未上传时禁用生成。
- 上传后展示文件名和解析状态。
- 户型解析结果从接口读取，不再写死。

确认后进入 Step 6。

### Step 6：做生成任务 API

目标：

- 用户点击生成全屋效果图后创建任务。
- 任务写入 `design_generation_jobs`。
- 前端轮询任务状态。

建议接口：

- `POST /api/design/jobs`
- `GET /api/design/jobs/[id]`

确认后进入 Step 7。

### Step 7：用 mock 结果跑通生成闭环

目标：

- 暂时不接真实图片生成模型。
- 后端模拟任务完成。
- 写入 mock 效果图数据到 `design_renders`。
- 前端展示真实数据库返回的结果。

确认后进入 Step 8。

### Step 8：接真实图片生成服务

目标：

- 后端根据户型解析结果和用户生成意图组 prompt。
- 调用图片生成模型。
- 生成图片保存到 Storage。
- 结果写入 `design_renders`。

确认后进入 Step 9。

### Step 9：接知识库检查

目标：

- 用户点击“用知识库检查全屋方案”。
- 后端把方案信息交给知识库检查逻辑。
- 检查结果写入 `design_reviews`。
- 前端展示施工、材料、预算风险。

确认后进入 Step 10。

### Step 10：上线验证

目标：

- 补齐 Vercel 环境变量。
- 验证 Supabase 表、Storage、API 权限。
- 线上完整跑通上传、生成、结果展示。

## 当前未做事项

- Supabase Storage bucket。
- 户型图解析。
- 生成任务表。
- 真实图片生成模型。
- 生成结果保存。
- 知识库检查结果保存。

## 注意事项

- 效果图生成模块不要复用 AI 装修顾问的聊天 UI。
- 知识库检查只能作为方案生成后的辅助能力。
- 不要在初始态展示假效果图或假解析结果。
- 不要让用户手动勾选生成空间，空间应来自户型图解析。
- 前端不要直接调用图片生成模型，统一走后端 API。
