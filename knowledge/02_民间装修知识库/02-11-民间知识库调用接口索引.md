# 民间知识库调用接口索引

## 一、文档目的

本文用于定义 `02_民间装修知识库` 在后期 RAG、AI 问答、装修顾问、监理助手、售后维权助手中的调用方式。

民间知识库不是用来替代标准答案，而是用来补充真实装修语境。它负责识别用户话里的“坑”“套路”“听说”“师傅说”“网上说”“入住后悔”“维权经验”等信息，再与标准知识库、决策案例库和规则库组合输出。

简单理解：

```text
用户问法负责触发
民间经验负责还原真实问题
标准知识负责校正
决策案例负责判断路径
规则库负责风险边界
模板库负责最终表达
```

## 三、用户意图与调用模块映射

### 1. 套路识别类

用户常见表达：

1. 这是不是套路。
2. 这家公司靠谱不靠谱。
3. 对方一直催我签合同。
4. 说今天不签就没有优惠。
5. 合同里没写清楚怎么办。

优先调用：

```text
02-01 装修公司与合同套路
02-02 预算增项与报价避坑
02-08 售后维权真实经验
02-10 民间经验可信度分级
```

必须联动：

```text
01_标准知识库/01_装修准备
01_标准知识库/11_售后保修
05_知识规则与风险控制
```

输出重点：

1. 不直接说“肯定是坑”。
2. 先指出需要核对的合同、报价、付款、材料、工期、保修明细。
3. 再判断是否属于高风险信号。
4. 给用户下一步沟通话术和证据留存建议。

### 2. 报价增项类

用户常见表达：

1. 水电为什么加这么多钱。
2. 报价单怎么看。
3. 半包报价很低能不能选。
4. 全屋定制后期为什么又加钱。
5. 哪些项目最容易增项。

优先调用：

```text
02-02 预算增项与报价避坑
02-01 装修公司与合同套路
02-05 全屋定制民间经验
02-10 民间经验可信度分级
```

必须联动：

```text
01_标准知识库/01_装修准备/01-02 装修预算制定
01_标准知识库/01_装修准备/01-06 装修报价单审核
01_标准知识库/03_水电工程/03-11 水电报价审核
```

输出重点：

1. 让用户提供报价单明细、工程量、计价方式、增项确认记录。
2. 把“合理增项”和“恶意漏项”分开。
3. 对水电、拆改、找平、大砖铺贴、定制五金、非标件等高频增项单独提示。
4. 给出可执行的核对表，而不是只讲原则。

### 3. 施工现场争议类

用户常见表达：

1. 师傅说这样没问题。
2. 工长说都是这么做的。
3. 现场看着不太对。
4. 这个是不是质量问题。
5. 我要不要返工。

优先调用：

```text
02-03 施工现场真实问题
02-09 师傅工长经验说法
02-10 民间经验可信度分级
```

必须联动：

```text
01_标准知识库/对应施工模块
01_标准知识库/09_验收标准
03_装修决策案例库/对应现场判断案例
05_知识规则与风险控制
```

输出重点：

1. 先判断问题是否涉及安全、隐蔽工程、防水、结构、用电。
2. 高风险问题不能只按经验说“没事”。
3. 要给用户现场核查动作，例如拍照、敲击、测量、打压、闭水、复验。
4. 明确哪些情况可以观察，哪些情况建议整改，哪些情况必须停工核验。

### 4. 材料口碑类

用户常见表达：

1. 这个品牌好不好。
2. 这个材料环保吗。
3. 某种材料是不是容易坏。
4. 网上说这个材料翻车是真的吗。
5. 便宜材料能不能用。

优先调用：

```text
02-04 材料品牌与口碑经验
02-07 入住后真实后悔清单
02-10 民间经验可信度分级
```

必须联动：

```text
01_标准知识库/对应材料模块
01_标准知识库/09_验收标准
05_知识规则与风险控制/产品安全和环保规则
```

输出重点：

1. 不做绝对品牌好坏结论。
2. 把品牌、型号、等级、检测报告、安装质量、售后服务分开判断。
3. 环保问题要提示“单品环保不等于全屋空气质量达标”。
4. 对五金、防水、板材、胶、腻子、乳胶漆、地板等耐用性和售后风险单独提示。

### 5. 全屋定制类

用户常见表达：

1. 投影面积报价靠谱吗。
2. 全屋定制为什么后期加钱。
3. 一门到顶会不会变形。
4. 封边重要吗。
5. 柜子怎么验收。

优先调用：

```text
02-05 全屋定制民间经验
02-02 预算增项与报价避坑
02-04 材料品牌与口碑经验
02-07 入住后真实后悔清单
```

必须联动：

```text
01_标准知识库/06_木工工程/06-04 定制柜基础知识
01_标准知识库/06_木工工程/06-05 柜体板材选择
01_标准知识库/10_软装家具/10-05 全屋收纳与柜体补充
```

输出重点：

1. 报价必须拆到板材、门板、背板、五金、抽屉、拉直器、灯带、封边、安装、运输。
2. 不能只比较单价。
3. 对超高门板、肤感膜、反弹器、玻璃门、开放格等要说明使用前提和维护成本。
4. 给下单前核对清单和安装验收清单。

### 6. 网红设计取舍类

用户常见表达：

1. 无主灯是不是智商税。
2. 岩板一体盆好不好。
3. 开放式厨房会不会后悔。
4. 隐形门实用吗。
5. 微水泥会不会翻车。

优先调用：

```text
02-06 网红设计翻车案例
02-07 入住后真实后悔清单
02-04 材料品牌与口碑经验
02-10 民间经验可信度分级
```

必须联动：

```text
01_标准知识库/10_软装家具
03_装修决策案例库/网红设计取舍案例
05_知识规则与风险控制
```

输出重点：

1. 不把网红设计简单说成“智商税”。
2. 判断用户家是否满足空间、预算、维护、采光、通风、清洁、施工条件。
3. 说明好看背后的施工要求和长期使用成本。
4. 给替代方案，例如保留局部效果、降低维护难度、减少非标做法。

### 7. 入住后悔类

用户常见表达：

1. 装修最容易后悔什么。
2. 插座是不是越多越好。
3. 开放格会不会积灰。
4. 卫生间怎么装才不后悔。
5. 哪些设计入住后不好用。

优先调用：

```text
02-07 入住后真实后悔清单
02-06 网红设计翻车案例
02-05 全屋定制民间经验
```

必须联动：

```text
01_标准知识库/03_水电工程/03-09 全屋开关插座规划
01_标准知识库/10_软装家具
03_装修决策案例库/软装家具决策案例
```

输出重点：

1. 把后悔原因拆成动线、收纳、清洁、照明、噪音、尺寸、维护、预算。
2. 不鼓励盲目堆配置。
3. 给“装修前怎么预防”的明细清单。
4. 对厨房、卫生间、卧室、客厅、阳台、玄关分别输出重点。

### 8. 售后维权类

用户常见表达：

1. 装修公司不维修怎么办。
2. 尾款要不要付。
3. 质保期内出问题找谁。
4. 材料和合同不一致怎么办。
5. 投诉前要准备什么。

优先调用：

```text
02-08 售后维权真实经验
02-01 装修公司与合同套路
02-10 民间经验可信度分级
```

必须联动：

```text
01_标准知识库/11_售后保修
05_知识规则与风险控制/责任判断与证据规则
04_AI问答模板库/维权沟通模板
```

输出重点：

1. 先让用户整理合同、报价、付款、聊天记录、照片视频、验收记录。
2. 再判断责任对象是装修公司、施工方、材料商、安装方还是业主使用维护。
3. 给沟通话术、整改期限、复验方式。
4. 对法律判断保持边界，必要时建议咨询当地消协、住建、市场监管或法律专业人士。

### 2. 弱触发词

以下词汇不一定单独触发民间库，但可作为辅助召回信号：

| 触发词 | 使用方式 |
|---|---|
| 怎么办 | 如果是现场或售后问题，联动 02-03 或 02-08 |
| 值不值 | 如果涉及设计、材料、定制，联动 02-04、02-05、02-06 |
| 要不要 | 如果涉及取舍，联动 02-06、02-07 |
| 正常吗 | 如果涉及施工现象，联动 02-03、02-09 |
| 能不能 | 如果涉及安全、验收、合同，联动标准库和规则库 |

## 五、RAG 召回建议

### 1. 第一轮召回

第一轮应根据用户问题召回最直接相关的民间经验条目。

示例：

```text
用户问：我家瓷砖空鼓，师傅说一点没事，怎么办？

第一轮召回：
02-09 师傅工长经验说法：瓷砖空鼓一点没事
02-03 施工现场真实问题：现场问题判断
02-10 民间经验可信度分级：B/C 级经验判断
```

### 2. 第二轮召回

第二轮必须召回标准库，不允许只用民间经验回答。

示例：

```text
继续召回：
01_标准知识库/05_瓦工工程/05-06 瓷砖空鼓处理
01_标准知识库/05_瓦工工程/05-10 瓦工验收标准
01_标准知识库/09_验收标准/09-05 瓦工工程验收标准
```

### 3. 第三轮召回

如果用户问题涉及具体决策，应召回案例库。

示例：

```text
如果用户问：要不要返工？

继续召回：
03_装修决策案例库/墙地面问题决策案例
03_装修决策案例库/验收判断决策案例
```

### 4. 最终校正

最终回答前应经过规则库校正：

```text
05_知识规则与风险控制/民间经验可信度规则
05_知识规则与风险控制/施工验收风险识别规则
05_知识规则与风险控制/高风险问题转人工规则
```

## 六、民间知识进入最终回答的结构

民间经验不应作为最终结论直接输出，而应采用以下结构：

```text
1. 这个说法/现象很常见
2. 它有一定道理，但要分情况
3. 哪些情况可以接受
4. 哪些情况风险较高
5. 对应的标准做法或验收依据
6. 用户现在可以做的检查动作
7. 下一步沟通或整改建议
```

示例：

```text
“瓷砖空鼓一点没事”这个说法很常见，但不能一概而论。

如果只是边角小面积空鼓，且不在打孔、挂件、淋浴区、高处墙砖等位置，风险相对低，可以先记录并观察。

但如果是大面积空鼓、整砖中心空鼓、墙砖高处空鼓、后期要安装五金的位置空鼓，或者空鼓伴随松动、开裂，就不建议忽视，应要求整改或复验。
```

## 七、与其他知识库的组合方式

| 用户问题类型 | 民间库作用 | 标准库作用 | 案例库作用 | 规则库作用 | 模板库作用 |
|---|---|---|---|---|---|
| 听说类 | 判断说法可信度 | 给正确做法 | 给类似场景 | 控制风险 | 组织回答 |
| 被坑类 | 识别套路 | 给合同和验收依据 | 给维权路径 | 判断责任边界 | 给沟通话术 |
| 现场类 | 还原真实争议 | 给验收标准 | 给判断步骤 | 判断是否高风险 | 追问信息 |
| 口碑类 | 提供真实反馈 | 校正材料参数 | 给选择方案 | 避免绝对评价 | 输出选购建议 |
| 后悔类 | 提供真实教训 | 给规划原则 | 给取舍案例 | 提醒长期风险 | 输出预防清单 |

## 八、可信度输出口径

民间知识最终输出时，可使用以下口径：

| 可信度 | 输出口径 |
|---|---|
| A | 这个经验比较可靠，可以作为重要参考 |
| B | 这个经验多数情况下有道理，但要看现场条件 |
| C | 这个经验有参考价值，但不能直接照搬 |
| D | 这个说法容易误导，建议按标准做法重新判断 |
| E | 这个做法风险较高，不建议采用 |

避免使用：

```text
绝对靠谱
肯定被骗
一定不能做
所有人都会后悔
某品牌一定不好
师傅一定在忽悠你
```

建议使用：

```text
风险偏高
需要进一步核对
要看合同和现场条件
这个说法有前提
建议先保留证据再沟通
建议按验收标准复核
```

## 九、典型问题调用示例

### 示例 1：瓷砖空鼓怎么办

用户问题：

```text
我家瓷砖空鼓，师傅说一点没事，怎么办？
```

调用路径：

```text
02-09 师傅工长经验说法
02-03 施工现场真实问题
02-10 民间经验可信度分级
01_标准知识库/05_瓦工工程/05-06 瓷砖空鼓处理
01_标准知识库/09_验收标准/09-05 瓦工工程验收标准
03_装修决策案例库/墙地面问题决策案例
05_知识规则与风险控制/施工验收风险识别规则
```

输出方向：

1. 先说这个说法常见，但要看空鼓位置、面积和用途。
2. 询问是墙砖还是地砖、空鼓面积多大、是否在边角、是否在淋浴区或挂件区。
3. 小范围边角空鼓可记录观察。
4. 大面积、中心、墙砖高处、打孔挂件区空鼓建议整改。
5. 给用户拍照、敲击标记、请监理或第三方复验的动作。

### 示例 2：报价低很多能不能签

用户问题：

```text
有家公司报价比别人低三万，能不能签？
```

调用路径：

```text
02-01 装修公司与合同套路
02-02 预算增项与报价避坑
01_标准知识库/01_装修准备/01-06 装修报价单审核
01_标准知识库/01_装修准备/01-07 装修付款方式
05_知识规则与风险控制/报价合同风险识别规则
```

输出方向：

1. 不直接否定低价。
2. 重点核对报价完整性、材料型号、工程量、增项单价、水电计价、付款节点。
3. 如果报价低但明细模糊，判定为高风险。
4. 建议要求对方补充报价明细和增项确认机制。

### 示例 3：无主灯是不是智商税

用户问题：

