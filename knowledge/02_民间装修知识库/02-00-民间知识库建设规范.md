# 民间知识库建设规范

## 一、概述

民间装修知识库用于收集真实装修过程中出现的踩坑经验、业主群问答、师傅说法、商家套路、平台评论、入住后悔、材料口碑和售后维权案例。

它不是标准知识库的替代品，而是标准知识库的真实世界补充层。标准知识库负责回答“专业上应该怎么做”，民间知识库负责回答“真实装修中大家怎么踩坑、怎么说、怎么被误导、怎么解决”。

民间知识库的最大价值在于让 AI 回答不再只是标准化说明，而是能理解用户真实语境：

1. 用户听到师傅一句话，不知道真假。
2. 用户看到网上经验，不知道能不能照做。
3. 用户遇到装修公司套路，不知道是不是合理。
4. 用户入住后后悔，不知道是否能提前避免。
5. 用户维权时，不知道别人怎么处理。

## 二、适用范围

本文适用于 `02_民间装修知识库` 下所有文档的采集、整理、校正、评级、结构化和后续 RAG 拆分。

适用内容包括：

1. 装修公司套路。
2. 预算增项经验。
3. 施工现场真实问题。
4. 材料品牌口碑。
5. 全屋定制经验。
6. 网红设计翻车。
7. 入住后悔清单。
8. 售后维权经验。
9. 师傅工长说法。
10. 短视频、社群、评论区高频观点。

## 三、民间知识库定位

### 1. 与标准知识库的区别

| 对比项 | 标准知识库 | 民间知识库 |
|---|---|---|
| 核心问题 | 正确做法是什么 | 真实世界怎么踩坑 |
| 内容来源 | 工程标准、流程、验收、专业经验 | 业主经验、师傅说法、评论、案例 |
| 组织方式 | 按装修流程和工种 | 按用户痛点和真实场景 |
| 输出方式 | 标准建议、验收清单 | 经验校正、避坑提醒、真实案例 |
| 风险 | 可能偏专业 | 可能不准确，需要校正 |

### 2. 民间知识库不做什么

民间知识库不应直接做以下事情：

1. 不直接把网上说法当结论。
2. 不直接给品牌下永久好坏判断。
3. 不传播无法验证的极端个案。
4. 不收录带有个人隐私的信息。
5. 不鼓励用户绕过安全规范。
6. 不替代法律、检测、施工专业判断。
7. 不把师傅经验当作唯一标准。

## 四、收录范围

### 1. 建议收录

| 类型 | 示例 |
|---|---|
| 高频踩坑 | 水电增项、全屋定制加钱、窗帘报价翻倍 |
| 真实后悔 | 插座位置不对、开放格积灰、无主灯太暗 |
| 师傅说法 | 空鼓一点没事、防水刷两遍就行 |
| 商家套路 | 免费设计、低价套餐、主材升级 |
| 维权经验 | 尾款保留、拍照留证、平台介入 |
| 材料反馈 | 某类材料易脏、难维护、售后麻烦 |
| 网红翻车 | 微水泥、岩板一体盆、隐形门、肤感膜 |

### 2. 不建议收录

| 类型 | 原因 |
|---|---|
| 单纯情绪吐槽 | 缺乏可复用知识 |
| 无法判断真假的指控 | 容易误导和侵权 |
| 只针对某个个人或门店的隐私信息 | 存在隐私和法律风险 |
| 没有场景的绝对结论 | 不利于 AI 判断 |
| 明显违反安全规范的做法 | 不能作为建议 |

## 五、来源类型

每条民间经验必须标注来源类型。

| 来源类型 | 说明 |
|---|---|
| 业主自述 | 业主描述自己的装修经历 |
| 业主群问答 | 群聊中高频问答和经验 |
| 短视频观点 | 抖音、小红书等内容观点 |
| 评论区经验 | 评论区大量重复出现的反馈 |
| 师傅说法 | 工长、工人、安装师傅经验 |
| 商家话术 | 装修公司、主材商、定制商销售话术 |
| 售后案例 | 维修、维权、投诉、赔偿经历 |
| 自有业务经验 | 自己业务中沉淀的真实问题 |

## 六、单条民间经验标准结构

每条民间经验建议采用以下结构：

```md
## 经验编号：02-模块号-序号

### 1. 民间原始说法

### 2. 来源类型

### 3. 适用场景

### 4. 经验总结

### 5. 可信度评级

### 6. 专业校正

### 7. 风险提醒

### 8. 用户常见问法

### 9. AI 回复模板

### 10. 关联标准知识

### 11. RAG 拆分建议
```

## 七、可信度评级规则

民间经验必须评级，不能不加判断地进入知识库。

| 等级 | 含义 | 输出方式 |
|---|---|---|
| A | 基本可靠，与标准知识一致 | 可直接作为建议 |
| B | 多数场景适用，但要看现场 | 说明适用条件 |
| C | 有参考价值，但不能绝对化 | 提醒用户不要照搬 |
| D | 容易误导，需要专业校正 | 明确指出问题 |
| E | 明显错误或有安全风险 | 不建议采用 |

评级必须参考：

1. 是否符合标准知识库。
2. 是否符合工程逻辑。
3. 是否有足够多案例支持。
4. 是否存在适用前提。
5. 是否可能造成安全风险。
6. 是否可能导致额外费用或售后风险。

## 八、专业校正规则

每条民间经验必须回连 `01_标准知识库`。

校正时要回答：

1. 这句话哪里有道理。
2. 这句话哪里不准确。
3. 什么情况下适用。
4. 什么情况下不适用。
5. 更稳妥的标准做法是什么。
6. 用户应该怎么判断。

示例：

```text
民间说法：瓷砖空鼓一点没事。

专业校正：
这个说法有条件成立。边角小面积空鼓风险相对低，但大面积空鼓、高处墙砖空鼓、后期要打孔区域空鼓，不建议忽视。应结合空鼓位置、面积、是否松动和是否影响安装判断。
```

## 九、隐私与版权处理

收录民间经验时应注意：

1. 不保留用户真实姓名、电话、地址。
2. 不直接复制长篇原文。
3. 不暴露具体门店、个人或施工队隐私。
4. 案例应做匿名化处理。
5. 平台内容应总结为经验，不全文搬运。
6. 涉及品牌口碑时避免绝对化和攻击性表述。

## 十、RAG 拆分规则

民间知识库后期适合细粒度拆分。

建议：

| 内容类型 | 拆分方式 |
|---|---|
| 单条经验 | 一条经验一个 chunk |
| 单个案例 | 一个案例一个 chunk |
| 单个师傅说法 | 一个说法一个 chunk |
| 单个 AI 模板 | 一个模板一个 chunk |
| 可信度规则 | 一个等级一个 chunk |

民间知识 chunk 建议带以下元数据：

```yaml
layer: folk
source_type: 业主群问答
credibility: C
risk_level: 中
scene: 全屋定制报价
related_standard_docs:
  - 01_标准知识库/01_装修准备/01-02
  - 01_标准知识库/10_软装家具/10-05
usable_for:
  - 民间经验校正
  - 避坑回答
  - 决策案例
```

## 十一、模块维护规则

1. 每个民间模块都应有明确主题边界。
2. 每条经验必须有可信度评级。
3. 每条经验必须有关联标准知识。
4. 高频经验可升级为决策案例。
5. 明显错误经验可以收录，但必须标注为 D 或 E。
6. 有安全风险的经验必须进入规则库。
7. 材料品牌口碑应定期复查，避免过时。

## 十二、用户输出规则

民间经验进入最终回答时，不应直接说：

```text
网上都这么说，所以你就这么做。
```

应表达为：

```text
这个说法很常见，但要分情况。
它有道理的地方是……
容易误导的地方是……
更稳妥的做法是……
你可以按这几步判断……
```
