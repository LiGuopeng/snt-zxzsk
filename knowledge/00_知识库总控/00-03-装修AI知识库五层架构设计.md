# 装修AI知识库五层架构设计

## 一、为什么要升级架构

当前 `01_标准知识库` 已经形成一套完整的装修专业知识库，内部包含 `01_装修准备` 到 `11_售后保修`，能够覆盖装修准备、施工、验收、软装和售后。

但如果未来要做 AI 装修客服、装修顾问、监理助手或内容创作系统，只靠专业知识库还不够。

用户真实提问通常不是标准化问题，而是带有现场条件、个人焦虑和民间说法的问题：

```text
装修公司报价很低靠谱吗？
水电增项是不是被坑了？
卫生间门口地板发黑是不是漏水？
全屋定制投影面积是不是套路？
无主灯是不是智商税？
瓷砖空鼓一点到底要不要修？
墙面开裂是不是正常？
师傅说这样做没事，可信吗？
```

这些问题需要的不只是“标准答案”，还需要经验、判断、模板和风险边界。

因此，知识库应从“单层文档库”升级为“五层知识系统”。

## 二、五层架构总览

```text
装修AI知识库五层架构
├── 第一层：标准知识库
│   └── 回答正确做法、流程、验收、责任
│
├── 第二层：民间经验库
│   └── 回答真实踩坑、套路、后悔、口碑
│
├── 第三层：决策案例库
│   └── 回答具体场景如何判断
│
├── 第四层：问答模板库
│   └── 控制 AI 如何表达
│
└── 第五层：可信度与规则库
    └── 控制风险、边界、评级和升级
```

这五层的关系是：

```text
标准知识库提供正确性
民间经验库提供真实性
决策案例库提供判断力
问答模板库提供表达力
规则库提供安全性
```

## 三、第一层：标准知识库

### 1. 定位

标准知识库是装修 AI 的专业底座。

它回答：

1. 装修流程是什么。
2. 每个工种怎么做。
3. 材料怎么选。
4. 验收怎么验。
5. 责任怎么判断。
6. 售后怎么处理。

### 2. 当前目录

```text
01_标准知识库
├── 01_装修准备
├── 02_拆改工程
├── 03_水电工程
├── 04_防水工程
├── 05_瓦工工程
├── 06_木工工程
├── 07_油工工程
├── 08_安装工程
├── 09_验收标准
├── 10_软装家具
└── 11_售后保修
```

### 3. 特点

| 特点 | 说明 |
|---|---|
| 稳定 | 多数内容长期有效 |
| 系统 | 按装修流程组织 |
| 可验收 | 能形成检查清单 |
| 可追责 | 能支持责任判断 |
| 可复用 | 适合客服、监理、培训和问答 |

## 四、第二层：民间经验库

### 1. 定位

民间经验库是装修 AI 的真实世界补充层。

它回答：

1. 装修中大家真实踩过什么坑。
2. 装修公司和商家常见套路是什么。
3. 网红设计为什么会翻车。
4. 入住后真实后悔点是什么。
5. 师傅和工长的说法到底能不能信。

```text
02_民间装修知识库

├── 02-01-装修公司与合同套路

├── 02-03-施工现场真实问题
├── 02-04-材料品牌与口碑经验
├── 02-05-全屋定制民间经验
├── 02-06-网红设计翻车案例
├── 02-07-入住后真实后悔清单
├── 02-08-售后维权真实经验
├── 02-09-师傅工长经验说法
└── 02-10-民间经验可信度分级
```

### 3. 单条经验格式

```text
民间原始说法
```

### 4. 注意事项

民间经验不能直接当标准答案。

每条经验都必须经过：

1. 可信度评级。
2. 专业知识校正。
3. 适用场景说明。
4. 风险提醒。

## 五、第三层：决策案例库

### 1. 定位

决策案例库是装修 AI 的判断层。

它解决用户的真实场景问题。

例如：

```text
卫生间门口地板发黑，是不是防水没做好？
水电增项 8000 元合理吗？
瓷砖空鼓一点要不要重铺？
全屋定制报价低是不是坑？
无主灯适不适合我家？
```

这些问题不能只靠标准条文回答，而要结合现场条件判断。


```text

```

### 4. 决策案例示例

```text
用户问题：
卫生间门口地板发黑，是不是防水没做好？

现场条件：
入住 3 个月，卫生间门口木地板发黑，淋浴区经常有水外溢，门槛石边缘胶缝开裂。

判断路径：
1. 先判断是否长期积水外溢。
2. 再检查门槛石和门套底部。
3. 再排查防水门口止水。
4. 必要时做局部含水率检测。

初步结论：
不一定能直接认定为防水失败，但高度怀疑门口存在潮气或渗水问题。
```

## 六、第四层：问答模板库

### 1. 定位

问答模板库是装修 AI 的表达层。

同样的知识，不同的表达方式会直接影响用户体验。

问答模板负责规定：

1. 用户问得模糊时怎么追问。
2. 用户焦虑时怎么安抚。
3. 涉及风险时怎么提醒。
4. 涉及责任时怎么保持边界。
5. 涉及民间经验时怎么校正。
6. 涉及报价合同时怎么给清单。

### 2. 建议目录

```text
04_AI问答模板库
├── 04-00-AI问答模板建设规范
├── 04-01-预算类问答模板
├── 04-02-合同类问答模板
├── 04-03-施工类问答模板
├── 04-04-验收类问答模板
├── 04-05-材料类问答模板
├── 04-06-全屋定制类问答模板
├── 04-07-软装类问答模板
├── 04-08-售后维权类问答模板
├── 04-09-风险提醒类问答模板
├── 04-10-追问澄清类问答模板
└── 04-11-AI问答模板库调用接口索引
```

### 3. 模板示例

```text
适用问题：
用户问“水电增项是不是被坑了？”

回答结构：
1. 先不直接判断被坑。
2. 说明要看原报价、点位变化、计价方式和现场施工量。
3. 给用户一张核对清单。
4. 提醒保留报价单和现场照片。
5. 建议让施工方列明增项明细。
```

## 七、第五层：可信度与规则库

### 1. 定位

规则库是装修 AI 的安全边界和判断规则。

它回答：

1. 民间经验可信度怎么分级。
2. 哪些问题属于高风险。
3. 哪些建议不能随便给。
4. 什么时候必须建议找专业人员。
5. 责任判断应该依据什么。
6. RAG 召回后如何选择更可信内容。

### 2. 建议目录

```text
05_知识规则与风险控制
├── 05-00-规则库建设规范
├── 05-01-民间经验可信度评级规则
├── 05-02-装修问题风险等级规则
├── 05-03-安全类问题回答边界
├── 05-04-责任判断与证据规则
├── 05-05-报价合同风险识别规则
├── 05-06-施工验收风险识别规则
├── 05-07-售后维权风险识别规则
├── 05-08-禁止建议与谨慎建议清单
├── 05-09-RAG召回与引用规则
├── 05-10-转人工与升级处理规则
└── 05-11-规则库调用接口索引
```

### 3. 规则示例

```text
如果用户描述漏水、漏电、燃气异常、吊柜松动、玻璃破裂等问题：
1. 优先提醒停用、关水、断电或远离风险。
2. 不直接让用户自行拆修。
3. 建议联系专业人员或责任方。
4. 再提供证据留存和排查路径。
```

### 示例 1：全屋定制报价

用户问：



## 十、最终判断

这套架构比“专业库 + 民间库”更完整。

原因是：

| 层级 | 解决的问题 |
|---|---|
| 标准库 | 知道正确做法 |
| 民间库 | 知道真实踩坑 |
| 案例库 | 知道怎么判断 |
| 模板库 | 知道怎么回答 |
| 规则库 | 知道边界在哪里 |

最终 AI 不只是资料检索器，而是具备判断力的装修顾问。
