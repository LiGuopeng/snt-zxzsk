# 用户真实问法映射表

## 一、文档定位

本文用于把用户口语化、错别字、模糊表达和情绪化提问，映射为知识库可识别的标准意图。

它不是正式知识正文，而是后期意图识别、RAG 召回、客服分流和评测集建设的基础蓝本。

后期如果迁移到后台系统，可转化为：

```text
用户问法表
意图训练数据
同义词词典
问题分类标签
召回策略配置
```

## 二、映射字段

每条问法建议包含以下字段：

| 字段 | 说明 |
|---|---|
| 用户原话 | 用户可能真实输入的句子 |
| 标准意图 | 系统内部识别后的问题意图 |
| 问题类型 | 流程、预算、合同、施工、验收、售后、民间经验等 |
| 所处阶段 | 设计前、施工中、验收前、尾款前、入住后、维权中 |
| 风险等级 | 低、中、高、紧急 |
| 是否需要追问 | 是或否 |
| 推荐召回链路 | 对应 `00-08-意图召回链路表` 中的意图编号 |
| 备注 | 方言、错别字、模糊点或特殊说明 |

## 三、问法归一规则

### 1. 错别字和口语优先识别意图

用户表达可能不标准，例如：

```text
墙面没们顺
刷完漆不平
水电是不是坑我
柜子味儿大
卫生间门口黑了
```

识别时不应机械匹配标准术语，而应判断用户关心的是：

```text
质量是否合格
是否需要整改
是否被坑
责任是谁
下一步怎么办
```

### 2. 同一问题按阶段拆分

同一句问题在不同阶段可能对应不同处理路径。

示例：

```text
墙面不顺
```

可能拆成：

| 阶段 | 标准意图 |
|---|---|
| 腻子后 | 腻子平整度验收 |
| 刷漆后 | 乳胶漆观感与基层平整判断 |
| 入住后 | 油工质量问题售后处理 |
| 尾款前 | 整改复验与付款节点 |

### 3. 情绪化表达要转成可判断问题

示例：

```text
装修公司是不是坑我？
师傅是不是忽悠我？
这个是不是翻车了？
```

不直接回答“是”或“不是”，应转成：

```text
报价是否有明细
施工是否符合验收要求
现场证据是否充分
是否存在高风险信号
```

## 六、维护规则

1. 新增高频用户问题时，应先归一为标准意图。
2. 一个用户问法可以对应多个阶段，但必须说明阶段差异。
3. 涉及安全、责任、赔偿、维权的问题必须标记风险等级。
4. 口语、错别字、简称和方言表达应保留原话。
5. 本表不替代知识库正文，只负责让系统理解用户在问什么。
