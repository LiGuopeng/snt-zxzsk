# 知识库调用与用户输出规则

## 一、文档目的

本文用于定义装修 AI 在面对用户提问时，如何调用五类知识库，并最终组织成可直接给用户看的回答。

前面的总控文档解决的是：

1. 知识库怎么建。
2. 目录怎么分。
3. 文档怎么写。
4. 标准库怎么被调用。

本文解决的是：

1. 用户问题进来后先判断什么。
2. 哪些知识库优先调用。
3. 标准知识、民间经验、案例、模板和规则如何组合。
4. 最终回答要按什么结构输出。
5. 哪些情况下必须提醒风险、追问或建议找专业人员。

## 二、五类知识库在回答中的角色

| 知识库 | 回答中的作用 | 是否直接展示给用户 |
|---|---|---|
| 01_标准知识库 | 提供正确做法、流程、验收、责任依据 | 是，转化为标准建议 |
| 02_民间装修知识库 | 提供真实踩坑、套路、后悔、师傅说法 | 是，但必须经过校正 |
| 03_装修决策案例库 | 提供类似场景的判断路径 | 是，转化为判断步骤 |
| 04_AI问答模板库 | 控制回答结构和语气 | 不直接展示，作为表达框架 |
| 05_知识规则与风险控制 | 控制安全边界、可信度、风险等级 | 是，转化为风险提醒 |

简单理解：

```text
标准库负责“对不对”
民间库负责“有没有坑”
案例库负责“怎么判断”
模板库负责“怎么说”
规则库负责“能不能这样说”
```

模板库已建立 `04-11-AI问答模板库调用接口索引`。后续回答用户问题时，应先完成事实召回、案例判断和风险校正，再调用模板库组织最终表达。

## 三、用户问题处理总流程

用户提问后，AI 应按以下流程处理：

```text
1. 识别问题类型
2. 判断风险等级
3. 判断用户所处阶段
4. 调用标准知识库
5. 如涉及经验、套路、口碑，调用民间知识库
6. 如涉及具体现象或取舍，调用决策案例库
7. 套用问答模板库组织表达
8. 用规则库做安全和边界校正
9. 输出最终回答
10. 必要时给出追问问题或下一步动作
```

## 四、问题类型与调用策略

### 1. 流程类问题

用户常见问法：

```text
装修流程是什么？
先做水电还是先做防水？
装修每个阶段要注意什么？
```

调用顺序：

```text
01_标准知识库/01_装修准备
01_标准知识库/09_验收标准
04_AI问答模板库/流程类模板
```

输出结构：

```text
先给结论
再列流程
再提醒关键节点
最后说明哪些节点必须验收
```

### 2. 预算报价类问题

用户常见问法：

```text
水电增项是不是被坑了？
装修报价单怎么看？
全屋定制报价为什么差这么多？
```

调用顺序：

```text
01_标准知识库/01_装修准备
01_标准知识库/03_水电工程 或相关模块
02_民间装修知识库/预算增项与报价避坑
03_装修决策案例库/预算合同决策案例
04_AI问答模板库/预算类模板
05_知识规则与风险控制/报价合同风险识别规则
```

输出结构：

```text
不直接判断是否被坑
先说明需要看哪些明细
列核对清单
指出高风险项
给下一步沟通建议
```

### 3. 合同维权类问题

用户常见问法：

```text
合同里没写清楚怎么办？
装修公司拖工期怎么办？
增项不提前说能拒绝吗？
```

调用顺序：

```text
01_标准知识库/01_装修准备
01_标准知识库/11_售后保修
02_民间装修知识库/装修公司与合同套路
03_装修决策案例库/预算合同决策案例
04_AI问答模板库/合同类或维权类模板
05_知识规则与风险控制/责任判断与证据规则
```

输出结构：

```text
先说明判断依据
再说明用户应保留哪些证据
再给沟通话术
最后说明升级路径
```

### 4. 施工标准类问题

用户常见问法：

```text
防水怎么刷才标准？
瓷砖空鼓多少算严重？
水电横平竖直是不是必须？
```

调用顺序：

```text
01_标准知识库/对应施工模块
01_标准知识库/09_验收标准
02_民间装修知识库/师傅工长经验说法
04_AI问答模板库/施工类模板
05_知识规则与风险控制/施工验收风险识别规则
```

输出结构：

```text
先给标准做法
再解释民间说法是否准确
再说明适用条件
最后给验收动作
```

### 5. 现场现象判断类问题

用户常见问法：

```text
卫生间门口地板发黑是不是漏水？
墙面开裂是不是正常？
地板踩着响是不是质量问题？
```

调用顺序：

```text
01_标准知识库/相关施工或售后模块
01_标准知识库/09_验收标准
03_装修决策案例库/对应现象案例
05_知识规则与风险控制/风险等级规则
04_AI问答模板库/追问澄清类模板
```

输出结构：

```text
先不武断下结论
列可能原因
给判断路径
说明先做什么
列需要补充的信息
提醒高风险情况
```

### 6. 民间经验校正类问题

用户常见问法：

```text
网上说防水越厚越好，对吗？
师傅说瓷砖空鼓一点没事，可信吗？
无主灯是不是智商税？
```

调用顺序：

```text
02_民间装修知识库/对应经验
02_民间装修知识库/02-11 民间知识库调用接口索引
01_标准知识库/对应专业模块
03_装修决策案例库/对应取舍案例
05_知识规则与风险控制/民间经验可信度评级规则
04_AI问答模板库/风险提醒类模板
```

输出结构：

```text
先说明这个说法是否常见
给可信度判断
说明对在哪里
说明错在哪里
给适用条件
给更稳妥做法
```

### 7. 软装家具类问题

用户常见问法：

```text
沙发怎么选尺寸？
窗帘报价怎么看？
床垫越硬越好吗？
```

调用顺序：

```text
01_标准知识库/10_软装家具
02_民间装修知识库/入住后真实后悔清单 或 材料口碑经验
03_装修决策案例库/软装家具决策案例
04_AI问答模板库/软装类模板
05_知识规则与风险控制/产品安全和环保规则
```

输出结构：

```text
先给选择原则
再给尺寸或参数清单
再列避坑点
最后给验收或下单前检查项
```

### 8. 售后保修类问题

用户常见问法：

```text
入住后漏水找谁？
装修公司不维修怎么办？
质保快到期要检查什么？
```

调用顺序：

```text
01_标准知识库/11_售后保修
01_标准知识库/09_验收标准
02_民间装修知识库/售后维权真实经验
03_装修决策案例库/售后维权决策案例
04_AI问答模板库/售后维权类模板
05_知识规则与风险控制/责任判断与证据规则
```

输出结构：

```text
先止损
再留证
再判断责任主体
再给报修沟通步骤
最后给升级处理路径
```

## 五、风险等级与输出要求

### 1. 高风险问题

以下问题必须优先提醒安全：

```text
漏水
漏电
燃气异常
承重墙拆改
吊柜或重物松动
玻璃破裂
高处瓷砖脱落风险
明显发霉伴随渗水
电器冒烟发热
```

输出要求：

```text
先提醒停用、断电、关水、远离风险
再给排查路径
不建议用户自行拆修高风险部位
建议联系专业人员或责任方
```

### 2. 中风险问题

例如：

```text
墙面开裂
瓷砖空鼓
地板起拱
木门变形
柜体发霉
家电报错
```

输出要求：

```text
先判断是否持续扩大
给记录方法
给初步排查路径
建议在质保期内报修
```

### 3. 低风险问题

例如：

```text
轻微色差
局部修补痕迹
软装搭配问题
轻微收纳不便
```

输出要求：

```text
给优化建议
说明是否需要立即处理
避免夸大风险
```

## 六、最终回答通用结构

多数回答建议采用以下结构：

```text
1. 直接结论
2. 判断依据
3. 具体检查或操作步骤
4. 风险提醒
5. 下一步建议
```

如果问题涉及民间说法，采用：

```text
1. 这个说法是否常见
2. 可信度评级
3. 哪部分有道理
4. 哪部分容易误导
5. 正确做法
6. 适用条件
```

如果问题涉及维权，采用：

```text
1. 先止损
2. 先留证
3. 判断责任
4. 联系对应责任方
5. 维修复验
6. 必要时升级投诉
```

## 七、回答边界

AI 回答时应避免：

1. 没有现场信息就直接判定责任。
2. 高风险问题中建议用户自行拆修。
3. 把民间经验当作绝对标准。
4. 把品牌口碑说成永久结论。
5. 对法律责任做绝对判断。
6. 对检测结果做无依据解释。
7. 只给结论不给判断路径。

更推荐表达：

```text
从你描述的情况看，更可能是……
但还需要确认……
建议你先做这几步……
如果出现以下情况，应尽快联系专业人员……
```

## 八、调用示例

### 示例 1：水电增项是不是被坑

用户问：

```text
水电增项 8000，是不是被坑了？
```

调用：

```text
01_标准知识库/01_装修准备/01-02 装修预算制定
01_标准知识库/01_装修准备/01-06 装修报价单审核
01_标准知识库/03_水电工程/03-11 水电报价审核
01_标准知识库/03_水电工程/03-13 水电增项风险
02_民间装修知识库/02-02 预算增项与报价避坑
05_知识规则与风险控制/05-05 报价合同风险识别规则
```

输出重点：

```text
不能只看金额，要看原报价是否漏项、点位是否变化、计价方式是否约定、现场是否确认、是否有增项单。
```

### 示例 2：师傅说瓷砖空鼓一点没事

用户问：

```text
师傅说瓷砖空鼓一点没事，可信吗？
```

调用：

```text
01_标准知识库/05_瓦工工程/05-06 瓷砖空鼓处理
01_标准知识库/09_验收标准/09-05 瓦工工程验收标准
02_民间装修知识库/02-09 师傅工长经验说法
05_知识规则与风险控制/05-01 民间经验可信度评级规则
```

输出重点：

```text
这个说法有条件成立。边角小面积空鼓风险较低，但大面积空鼓、高处墙砖空鼓、后期要打孔区域空鼓，不建议忽视。
```

### 示例 3：卫生间门口地板发黑

用户问：

```text
卫生间门口地板发黑，是不是漏水？
```

调用：

```text
01_标准知识库/04_防水工程/04-09 漏水原因分析
01_标准知识库/09_验收标准/09-04 防水工程验收标准
01_标准知识库/11_售后保修/11-03 漏水渗水售后处理
03_装修决策案例库/03-04 漏水渗水决策案例
05_知识规则与风险控制/05-02 装修问题风险等级规则
```

输出重点：

```text
不能直接判定防水失败，但这是需要尽快排查的潮湿或渗水信号。先停止门口积水，拍照记录，检查门槛石、门套底部和地板含水情况。
```

## 九、维护规则

1. 新增知识库类型时，必须更新本文。
2. 新增高频用户问题时，应补充调用示例。
3. 新增风险规则时，应同步更新输出边界。
4. 民间知识库已建立可信度规则，后续新增民间经验时应同步维护可信度评级和输出口径。
5. 决策案例库已建立 `03-11-决策案例库调用接口索引`，后续新增案例时应同步维护案例调用映射、风险等级和输出结构。
6. 规则库已建立 `05-11-规则库调用接口索引`，最终回答输出前必须经过风险等级、禁止建议、责任边界和转人工规则检查。
